# 13 分點排行與追蹤(規劃;2026-07-07 使用者需求)

> 目標:一張「值得追蹤的分點」排行表 + 「這些分點在最近可用交易日買賣什麼」動向表,含權證分點視角。
> 本文件把 04 §2–5(分點模型)與 09(足跡)落成**可直接開工的功能規格**。
> **前提:分點資料尚未解鎖**(見 §6)。資料一到位,本規格即可實作,無需再議。

## 1. 功能一句話

盤後自動回答兩個問題:
1. **誰值得追?** —— 分點可信度排行榜(演算法算出高勝率、會賺錢、非隔日沖的分點)
2. **他們最近交易日買賣了什麼?** —— 追蹤名單分點的每日進出明細(股票 + 權證)

### 2b. 演算法自動入選(每週六重算,04 §5 可信度分數)

入選條件(全部滿足):
1. 近 2 年「進場事件」≥ 10 次(事件 = 單股單日淨買超 ≥ 該股成交值 1%,連續日合併)
2. 可信度分數 ≥ 70(構成:5 日勝率 30% + 平均報酬 25% + 買點分位 15% + 非隔日沖 10% + 近 90 日仍有效 20%)
3. 非隔日沖(買超次日回吐 ≥70% 的比率 < 60%)
4. 近 90 日仍活躍(事件 ≥ 2)

自動移出:連續 60 日可信度 < 50 或不活躍。`source='auto'`,與手動名單並存,UI 標示來源。

## 3. 排行榜演算法(每日/每週計算)

### 3a. 分點×個股統計(`branch_stock_stats`,05 已定義)

每事件記錄:進場日、均價(以次日開盤計,避免 T+1 偷看)、張數、金額、後 1/3/5/10/20 日報酬。
彙總:事件數、勝率(5日>0)、平均/中位報酬、最大回撤、買點分位(買在近 20 日區間低點程度)、隔日沖率、持有型態(短線/波段)。

### 3b. 分點總排行(跨個股彙總)

```
排行分 = 0.30×勝率(40%→0分,70%→滿分)
       + 0.25×平均5日報酬(0%→0,+5%→滿分)
       + 0.15×買點品質(買低分位)
       + 0.10×規模(近90日買超總金額,log 級距──太小的分點統計無意義)
       + 0.20×近效性(近90日 vs 全期報酬衰減)
隔日沖判定成立 → 單獨列「隔日沖分點榜」,不進主榜(它們是反指標/風險訊號來源)
```

### 3c. 權證分點(同一套,兩個差異)

1. **資料面與跨權證彙總**：權證代號理論上為獨立個體，但因一檔熱門股票常同時有多檔權證發行，分點大戶通常會分散買進多檔。故實作上以「標的股」為中心，將單一分點對同一標的下「所有權證」的買賣張數，乘上該日權證收盤價，加總出該分點對該標的的「權證淨買賣金額」。
2. **統計面與時間維度**：為了捕捉大戶在不同週期的佈局，我們將時間維度切分為 **1D / 2D / 5D / 30D / 120D**。全市場 `/branch` 探索仍以 `abs(淨買賣超) >= 500 萬` 作大額門檻；個股詳細頁是較寬的證據視角，先讀 `branches/warrant-stock-details/index.json`，再依股票讀取 `{stock_id}.json` 分片，以 `>=100 萬` 顯示，100–499 萬只標「觀察」、不視為全市場大額訊號。兩者皆明示熱門上市權證與每檔前 15 大分點裁剪限制。

## 4. 頁面規格(掛在 探索 → 分點)

### Tab「分點排行」
| 欄 | 內容 |
|---|---|
| 分點 | 券商-分點名(點入 → 分點視角頁) |
| 來源 | 手動/自動 徽章 |
| 可信度 | 0–100,≥70 亮黃 |
| 5日勝率 / 平均報酬 | 樣本數 <10 顯示「樣本不足」 |
| 型態 | 波段 / 短線 / 隔日沖(紅) |
| 近90日 | 事件數 + 買超金額 |
排序:可信度;篩選:最少樣本數、排除隔日沖、只看手動名單。

### Tab「分點最近交易日進出」(核心使用場景)
`branches/today.json` v1 = `{version: 1, as_of, movements}`。export 以價格日為上限，取**追蹤分點實際存在的** `MAX(branch_trades.date)` 作 `as_of`，再列該日全部 tracked movement；無資料時為 `as_of: null, movements: {}`。前端仍接受舊 bare mapping（code 先於 data 部署時不冒稱日期）。

每列為分點｜股票（點入個股頁）｜買進張｜賣出張｜淨買賣張｜佔比；買進／賣出是中性 gross 值，淨值正紅、負綠、零中性，`pct=null` 顯示「—」。保留最近可用分點資料日，不以價格日或「今日」冒稱。排序沿用分點後淨買賣；高可信度分點與綜合分的交集只可作 UI 提示，不變更 04 §2 B5 給分。

### 分點視角頁(點任一分點)
近 90 日操作時間軸(買賣超 × 股票)、績效統計卡、擅長產業/題材分布、在追蹤個股上的 K 線足跡連結(09)。

### 分點逐日明細的 bounded 聯集（2026-08-31 已落地）

`branches/track/index.json` 的 detail set 不再只限 `tracked_branches`：它是所有 tracked 分點，聯集最新 `branch_rankings` 快照中 `is_daytrade=0`、依 `rank_score DESC, samples DESC` 的前 100 名。去重時 tracked source 優先；只因排行入選的分點保留 `candidate`／`auto` 等來源並可產 lazy shard。這不改排行、統計、分數、資料表或追蹤 seed。

三層 hard cap 為 ranking Top100、聯集最多 200 branches、每 shard 最多 20,000 rows。tracked 分點本身若超過 200，export fail closed，絕不靜默省略；尚有容量才依排名順序加入 ranking-only。每 shard 限在 export date 以前的 120 日視窗；即使 `daily_prices` 無法提供裁切下緣，仍只保留最新 20,000 rows 並標 `truncated`。payload `as_of`、index `first_date`／additive `last_date` 均取實際資料列日期，沒有 rows 的 tracked shard 仍存在且三者皆為 null。前端可讀舊 index／shard；只有 ready index 命中的排行卡才可下鑽，其他如實標「僅有排行」。索引或 shard contract/fetch 失敗不能偽裝成 empty，排行榜仍可使用；empty 只表示該 120 日視窗未進每日前 15 大買／賣超，不代表沒有交易。

發布前唯讀容量 evidence：排名 831、舊 history index 47；`華南永昌-大安` 排第 8、近 120 日依現行口徑有 4,887 rows，但原本僅是 candidate。tracked+非隔日沖 Top100 聯集為 138 分點／599,525 rows，估約 22.9 MiB；這是當次估算，不是對未來資料量的保證，實際上由三層 hard cap 約束。其後已受控同步、export/deploy；正式 index 為 138，該 shard 實際為 4,824 rows／83 交易日。未改 DB／cron。

### 權證大戶 Tab (原權證分點)
以 Bento Grid 卡片呈現，並提供 `1D / 2D / 5D / 30D` 的快速切換 (Pill Selector)。
卡片重點展示：分點名稱、標的名稱與代號、醒目的淨買賣金額 (大買/大賣標籤)。僅顯示淨買賣超 > 500萬台幣 的主力大戶。
**互動設計**：支援點擊卡片向下展開明細 (Accordion)，顯示構成該大單的所有權證清單 (代號、名稱、認購/售、貢獻金額與佔比)，並依金額自動排序。

免費方案的誠實限制:
1. **只有前 15 大**——小額分點看不到(對追主力夠用)。
2. **只涵蓋每日評分池 80 檔**——冷門股沒有分點史;統計偏向熱門股。
3. 非官方頁面,改版/限流風險 → parser 掛掉會進 import_logs 告警;低頻(每晚一輪、3 秒節流)降低風險。
4. 歷史回補淺:從接入日往後累積;`--date` 可逐日補近月,別暴力回補一年。
5. **統計效力需要時間**:可信度分數要 ≥10 次事件,約累積 2–3 個月後排行榜才可信;之前先出「今日動向」表(§4 Tab 2)。

原 FinMind-only 行動點作廢;實作順序改為:資料累積(已開始)→ 今日動向頁 → branch_stock_stats → 排行榜 → 權證分點。

## 7. 誠實限制(UI 要標)

1. 分點資料 T+1 或更晚；「分點最近交易日進出」必顯示 export 的 `as_of`，不可用價格日或「今日」替代。
2. 分點 ≠ 單一人:大分點混雜多帳戶,統計是機率不是身分證。
3. 勝率以「次日開盤進場」計算,與分點實際成本有差。
4. 名單公開的知名分點常被跟單,訊號會衰減——近效性權重 20% 就是為此設計。

## 8. 2026-08-27 現況稽核（唯讀）

- 現行分點事件為淨買超達門檻的連續段首；以次一交易日開盤進場、第五根有效還原收盤計算，`win` 嚴格為 5 日報酬 `> 0`。
- `samples` 含尚未成熟事件，但勝率只納入已成熟樣本；目前 ≥5 事件即可進排行，而 UI 對 <10 樣本標示不足。隔日沖觀測最低 4 筆，與本文件原規劃 ≥8 不一致；排行／export 另受前 15 大分點資料截斷。
- 建議 V2：分離 `events_count` 與 `matured_samples`；成熟樣本 <10 不評分、10–29 暫定、≥30 充分；隔日沖最低 8 筆且缺資料記 `unknown`；以 point-in-time shadow diff 驗證排行漂移。
- V2 會改變排行，涉及 schema 與正式 DB 回算，須另次人工確認；本次未改排行、schema 或正式資料。
