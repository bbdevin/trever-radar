# 40. 「期貨先爆量、現貨未跟上」之後的可交易日大漲次數 —— 事前登記(草案)

> **狀態:草案,尚未凍結。** 使用者看過、同意之後才 commit 凍結版並把 hash 記進 `docs/STATUS.md`;在那之前任何人**不得**查詢這些訊號之後的股價表現。凍結版之後,本文件每一個數字與規則都不得在資料可見後修改(同 `docs/38` §0)。
>
> **使用者原話**:「隔天大漲的股票篩選機率功能」(2026-09);`docs/39` 以綜合榜為條件做了一次,樣本不足而擱置(n=23)。2026-10-02 使用者同意改用出現次數較多的訊號:**期貨成交量創新高、而當天現貨量還沒創新高**(`docs/38` 的 F_only,檢定 B 已通過的那一種)。
>
> **為什麼可以直接用歷史資料**:事前登記的效力來自「規則寫死時沒人看過結果」,凍結觸發在**資料可見**,不是某個日期。`docs/38` 的檢定量的是 F_only 之後**現貨成交量**有沒有創高;**從來沒有人查過 F_only 之後的股價**。§9 逐項揭露凍結前已看過的東西。

## 0. 名詞

- **訊號日 t**:某檔股票至少一個個股期貨契約在 t 依 `docs/38` §1–§2 舉旗,**且** `spot_new_high(s, t) = false`(現貨當日未同步創高,即 F_only)。同一檔同一天兩個契約(標準型與小型)舉旗,算**一次**(單位是股票,因為結果量的是股價)。
- **事件**:同一檔股票在連續期貨交易日都符合訊號,只取**第一天**(`docs/39` 的慣例;避免同一波被數好幾次)。
- **可見日 v(t)**:旗標要到 t 的下一個期貨交易日 21:2x 才看得到(`docs/38` §7.8:day t 的報告要到 t+1 05:00 才完整,21:20 那輪匯入的是 t−1)。v(t) = t 之後第一個市場交易日。
- **進場日 e(t)**:v(t) **之後**的第一個市場交易日——讀者最早買得到的那一天。**不是 t+1。** 用 t+1 的漲幅等於統計一個買不到的報酬。
- **大漲(主要結果)**:`100 × close(s, e) ≥ 103 × open(s, e)`——進場日開盤買、收盤計 **≥ +3%**,原始價、同一列(還原因子相消)。不含開盤跳空(買不到)。
- **對照**:同 `docs/39` §3.3 的兩組等量對照,換成這個訊號的母體(§3.3)。

### 為什麼是 +3%,不是 docs/39 的 +7%

`docs/39` 借用了專案裡唯一寫成數字的「大漲」(+7%)。這裡改成 +3% 的理由是**檢定力**,而且是在看資料之前講的:有個股期貨的標的多是中大型股,日內開盤到收盤漲 ≥ 7% 在一般市場經驗裡大約只佔百分之一上下的股票日;約 600 個事件只會有個位數命中,檢定 A(命中 ≥ 30)必然不過——那等於事先就知道會「樣本不足」。+3% 在這類股票約佔百分之幾,600 個事件約數十次命中,**才有機會**被檢定。+5%、+7% 仍然列為**只報告**的伴隨計數(§3.6),不作判準。

這個選擇的代價也事先講:+3% 對「大漲」是寬的。若過關,畫面上必須照實寫「≥ +3%」,不得寫成「大漲」兩字而不附門檻。

## 1. 統計量(全部是整數或日期)

| 欄位 | 內容 |
|---|---|
| `from` / `to` | 第一個與最後一個事件的訊號日 |
| `events` | 成熟且未被否決的事件數 n |
| `hits` | 其中進場日開盤到收盤 ≥ +3% 的次數 h |
| `placebo_stock_hits {min, max}` | 同股對照十組 seed 的命中數範圍 |
| `placebo_date_hits {min, max}` | 同日他股對照十組 seed 的命中數範圍 |
| `drops` | 進場日開盤到收盤 ≤ −3% 的次數(**方向檢查**,見 §3.5) |
| `threshold_pct` | 恆為 3 |
| `leg` | 恆為 `"entry_open_to_close"` |

除法由人做,不出比率、機率、百分比(同 `docs/38` §1、`docs/39` §1)。

## 2. 否決(該事件兩臂都不進,也不算未命中)

- **R1 不成熟**:e(t) 不存在或晚於 as_of;(s, e) 沒有價格列;開盤為 NULL 或 ≤ 0;收盤為 NULL。
- **R2 停牌／處置**:e 日成交量為 0 或 NULL。處置股無法偵測(`schema.py` 沒有該表),記為盲點(同 `docs/39` R5)。
- **R3 鎖漲停開盤**:不否決,是結構性未命中(開盤即漲停,開盤到收盤 ≤ 0)。只報告 `entry_open_at_limit_proxy`。

## 3. 全案否決(過不了就不上線)

### 3.1 樣本

- **as_of**:`daily_prices` 與 `futures_daily` 都已匯入的最後一天。
- **評估期**:`futures_daily` 的第一個交易日到 as_of(目前約 250 個期貨交易日)。
- **對半**:評估期的市場交易日依 `branch_window_direction_battery.split_window` 慣例對半(奇數多的一天歸後半)。

### 3.2 檢定 A(檢定力)

`n ≥ 30` **且** `h ≥ 30`(`LOW_SAMPLE_SURVIVORS`,import 不重寫)。不足 = **UNDERPOWERED**,是無結果不是否證;累積 ≥ 60 個新市場交易日後才可重跑一次。

### 3.3 檢定 B(資訊性:比平常的日子多)

兩組等量對照,seed 0..9(`PLACEBO_SEEDS`、`seed_result` 從 `futures_volume_battery` import),**20 個判準全部** `h − h_P ≥ 2σ_P`:

- **P_stock(同股、同半段)**:同一檔股票、同一半段、**當天沒有任何契約舉旗**的期貨交易日,進場規則相同(同樣往後推到 e)、R1–R2 通過。依 (股票, 半段) 等量抽。
- **P_date(同日、他股)**:同一個訊號日 t、**有個股期貨但當天沒有舉旗**的其他股票,同樣的 e。依日期等量抽。

P_stock 吸收「這檔股票本來就常大漲」;P_date 吸收「那幾天整個市場都在漲」。抽不滿 → NOT EVALUABLE,逐項列出。

### 3.4 檢定 C(兩半各自成立)

每一半、每一組對照、每一個 seed:`h(半) − h_P(半) > 0`。擋「全部的優勢來自某一個月」。

### 3.5 方向檢查(判準,不是只報告)

量的訊號可能只是預告**波動**,不是方向。所以加一條:**`h − drops > 0`**(大漲次數多於大跌次數)。不成立 → 不上線,STATUS 記「這個訊號預告的是波動,不是上漲」——那本身是一個有用的結論,但不是使用者要的功能。

### 3.6 伴隨計數(只報告,永遠不是判準)

+5%、+7% 的命中數(訊號與兩組對照各一);`entry_open_at_limit_proxy`;依月份的 events / hits;e 日距訊號日的交易日數分布(應全為 2);同一檔股票兩個契約同日舉旗的次數。

### 3.7 裁決

A、B(20 個判準全過)、C、§3.5 全部成立 → **上線**;其餘一律不上線。任一 NOT EVALUABLE → 不上線。每次執行把 §1 全部欄位、每個 seed 的 h_P / σ_P、兩半的 h / h_P、否決計數、伴隨計數、裁決寫進 STATUS,原始 JSON 進 `docs/evidence/`。

### 3.8 不允許的補救

改 3、改進場日、改「開盤到收盤」、改事件合併規則、改對照池定義、改 30 / 2σ / seed、改成 t+1 進場、換成 +5% 或 +7% 當主要結果——都只能開新版本,並只用新版本 commit 之後才出現的交易日。

## 4. 執行順序(每一步之間不看資料)

1. 使用者同意 → commit 凍結版,hash 記進 STATUS。**在此之前不查任何 F_only 之後的股價。**
2. 只記錄涵蓋度:評估期起訖、F_only 契約日數、去重後事件數(不是結果)。
3. 實作唯讀 battery(`next_day_futures_signal_battery.py`),測試用自造 fixture;上正式資料前交獨立驗證者挑錯(`docs/39` 的教訓:9 個錯誤實作曾通過全部測試)。
4. 跑一次,紀錄寫入 STATUS。
5. **只有通過**才上線:期貨分頁與個股期貨分頁加一句,逐字鎖在 `lib/`:
   > 「{from} 至 {to},期貨先爆量、現貨未跟上的訊號共 {events} 次;訊號可見後第一個交易日開盤買、收盤漲 ≥ 3% 的有 {hits} 次。同一批股票平常的日子 {P_stock} 次,同一天其他股票 {P_date} 次。這是次數,不是機率;不含開盤跳空。」

## 5. 明確不做

不做個股數字(一檔幾次事件沒有分母);不依「大漲可能性」排序股票;不出百分比;不把 t+1 當進場日;不做多日持有報酬(那是另一個問題)。
