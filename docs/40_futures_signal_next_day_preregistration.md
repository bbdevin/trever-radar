## 0. 名詞

- **母體**:`futures_contracts` 的標的股中 `stocks.type = 'stock'` 者。ETF 期貨的標的不進任何一臂(使用者要的是股票;ETF 的日內 ±3% 結構上罕見,只會稀釋)。
- **市場交易日曆 D**:`daily_prices` 任一列存在的日期集合(同 `docs/38` R4、`docs/39` §0)。
- **期貨交易日曆**:`futures_daily` 出現過的日期集合(同 `docs/38` §0)。
- **契約-日判讀**:一律呼叫 `futures_volume_battery.evaluate_contract_day_in_calendar`,R4 排除日一律由 `settlement_exclusion_set` 產生,現貨旗標 `S(s, t)` 一律由 `spot_new_high` 產生——**import,不重寫**。這裡檢定的必須是上線中的那一條規則本人。
- **訊號日 (s, t)**:t 是期貨交易日、t ∉ R4 排除日、s 至少一個契約在 t **無否決且 `flag = True`**,**且** `S(s, t)` **已知為 False**。`S` 未知 → 不是訊號日(未知 ≠ 否,同 `docs/38` §6.5)。同一檔同一天兩個契約都舉旗,算**一個**訊號日(單位是股票,因為結果量的是股價)。**不套用** `docs/38` 的「往後 5 個現貨日成熟」條件——那是另一個往後看量的成熟性;本文件的成熟性只看 §2 R1。
- **事件**:s 的訊號日 t,若期貨交易日曆上 t 的**前一個**期貨交易日 s 不是訊號日,t 是事件(連續段取首日;R4 排除日不可能是訊號日,所以會切斷段落)。段落先在完整日曆上認定,**然後**才套用剔除窗 X。
- **剔除窗 X**:訊號日 t ∈ [**2026-09-18**, **本文件凍結 commit 的日期(台北時間)**] 的整段日子。理由見 §6:期貨旗標自 2026-09-21(`0b126e6`)起在正式站與 K 線並排顯示,當時最大期貨日為 09-18,所以 t ≥ 09-18 的旗標可能被人「看見舉旗、再看見之後的走勢」;那正是讓假說被軼事挑出來的管道。X 內的日子**兩臂與兩個對照池一起剔除**,也不進對半用的日曆。凍結之後的日子不受影響。
- **可見日 v(t)**:D 中 t 之後的**第 1 個**市場日。旗標在 v(t) 的 21:2x 那一輪才第一次出現(`docs/38` §7.8,正式機實測:09-21 那輪匯入的是 09-18)。
- **進場日 e(t)**:D 中 t 之後的**第 2 個**市場日——讀者最早買得到的那一天。由日曆算,不由任何儲存欄位讀。用 t+1 的漲幅等於統計一個買不到的報酬。
- **漲 ≥ 3%(hit)**:`100 × close(s, e) ≥ 103 × open(s, e)`。**跌 ≥ 3%(drop)**:`100 × close(s, e) ≤ 97 × open(s, e)`。原始價、同一列(與 `adj_factor` 結構上無關,除權息日也一樣),比較用十進位(同 `next_day_surge_battery._dec`)。不含 v(t) 收盤到 e 開盤的跳空(買不到)。
- **as_of**:期貨與現貨**都已匯入**的最後一天 = `min(max futures_daily.date, max daily_prices.date)`,由程式讀出並強制,不由人挑(同 `docs/39` 的 `check_as_of`;`--historical` 只供重現舊裁決,寫進報告)。

### 為什麼是 +3%,而且不叫「大漲」

`docs/39` 借用了專案裡唯一寫成數字的「大漲」(+7%)。這裡改成 +3%,理由是**檢定力**,在看資料之前寫下:

| 門檻(開盤到收盤) | 事前預估的基礎率(一般市場經驗,不是本資料庫算的) | n ≈ 500–600 時對照組約幾次 | 結論 |
|---|---|---|---|
| ≥ +7% | 約 0.5–1% | 3–6 | 檢定 A(h ≥ 30)必然不過 |
| ≥ +5% | 約 1.5–3% | 8–18 | 檢定 A 幾乎必然不過 |
| **≥ +3%(採用)** | **約 6–10%** | **30–60** | **才有機會被檢定** |

有個股期貨的標的多是中大型股,日內 +3% 約是 1.5 倍標準差的日子:對它們是「明顯上漲」,不是「大漲」。**代價事先講**:畫面與文件一律寫「漲 ≥ 3%」,**不得**寫「大漲」二字。+5%、+7% 只列伴隨計數(§3.6)。這張表的數字被寫下來,是讓日後讀者看得到事前預估,不是門檻,不參與任何判準。

## 1. 統計量(全部是整數或日期,除了 `leg` 這個固定字串)

| 欄位 | 內容 |
|---|---|
| `from` / `to` | 第一個與最後一個事件的訊號日 |
| `events` | 成熟且未被否決的事件數 n |
| `hits` | 其中 e 日漲 ≥ 3% 的次數 h |
| `drops` | 其中 e 日跌 ≥ 3% 的次數 d |
| `placebo_stock_hits` / `placebo_stock_drops` `{min, max}` | P_stock 十組 seed 的 h_P / d_P 範圍 |
| `placebo_date_hits` / `placebo_date_drops` `{min, max}` | P_date 十組 seed 的 h_P / d_P 範圍 |
| `threshold_pct` | 恆為 3,從模組常數讀 |
| `leg` | 恆為 `"entry_open_to_close"` |

除法由人做,不出比率、機率、百分比(同 `docs/38` §1、`docs/39` §1)。**跌的次數與漲的次數一定一起出現**:只給漲,會把一個波動訊號讀成方向訊號。

## 2. 否決(per 事件、per 對照日;命中 → 不進分母、也不算未命中)

- **R1 不成熟或無列**:e(t) 不存在,或 e(t) > `max daily_prices.date`;(s, e) 沒有價格列;`open` 為 NULL 或 ≤ 0;`close` 為 NULL。
- **R2 停牌**:e 日 `volume` 為 0 或 NULL。
- **R3 鎖漲停開盤**:**不否決**,是結構性未命中(開盤即漲停,開盤到收盤 ≤ 0),兩臂同一條規則。只報告 `entry_open_at_limit_proxy` = `open(s, e) ≥ 1.095 × close(s, v)` 的事件數(原始價;e 為除權息日時低估,標明)。
- **已知盲點(記錄,不處理)**:處置股(`schema.py` 沒有該表,偵測不到;同 `docs/39` R5)。

## 3. 全案否決(過不了就不上線,不是「上線但加註」)

### 3.1 樣本

- **評估期**:從「母體中至少一個契約-日被規則看過且無否決」的最早期貨交易日,到 as_of。(不是 `futures_daily` 第一天:前 60 個期貨日窗口湊不滿,R1 全數否決,拿進來對半會讓前半幾乎沒有事件——`docs/39` 評估期起點的同一個教訓。)
- **對半**:評估期內、**扣掉 X** 的市場交易日,依 `branch_window_direction_battery.split_window` 慣例對半(奇數多的一天歸後半),記 H1、H2。事件與對照日依其**訊號日**歸半。
- **合格對照日 (s, d)**(兩組對照共用,逐條都要成立):
  1. s 在母體;d 是期貨交易日、d ≤ as_of、d ∉ R4 排除日、d ∉ X;
  2. s 至少一個契約在 d 被規則看過、**無否決**、`flag = False`;
  3. s **沒有任何**契約在 d 舉旗(不論 `S` 為真、假或未知),也沒有任何契約在 d 以 `R2b_immaterial` 被否決(那是「創了新高但不夠實質」的日子,不是平常的日子);
  4. `S(s, d)` **已知為 False**——與事件同一個條件。對照問的是「當天現貨沒創高的日子裡,期貨創高有沒有多告訴你什麼」;把現貨爆量日放進對照,比的就是另一個問題;
  5. (s, e(d)) 通過 §2 R1–R2。
- **刻意不從池子排除的日子**:事件前後、但本身不是訊號日的日子。同一檔股票的 e(d) = e(t) 若且唯若 d = t,所以對照日與事件**不會共用同一個結果日**;它們是「沒有訊號的日子」,正是基礎率本身。這一條事前登記為**不可用的補救**:檢定失敗後,「池子被事件鄰日汙染」不能當重做的理由。

### 3.2 檢定 A(檢定力)

`n ≥ 30` **且** `h ≥ 30`(`LOW_SAMPLE_SURVIVORS`,import 不重寫)。不足 = **UNDERPOWERED**:檢定力不足的無結果,不是否證。

### 3.3 檢定 B(資訊性:比平常的日子多)

- **P_stock(同股、同半段)**:對每個 (股票 s, 半段 h),s 在 h 有 k 個事件,就從 s 在 h 的合格對照日不放回抽 k 天。
- **P_date(同日、他股)**:對每個有 k_t 個事件的訊號日 t,從 t 當天其他股票的合格對照日不放回抽 k_t 個。
- seed 固定 0..9,兩組各自抽(`PLACEBO_SEEDS`、`seed_result`、`PLACEBO_SIGMA_MULTIPLE` 從 `futures_volume_battery` import;抽法同 `next_day_surge_battery.draw_matched`:鍵排序後依序抽、不重複、不跨鍵借)。
- **判準**:每組對照、每個 seed,`p̂ = h_P / n`、`σ_P = max(1, sqrt(n·p̂·(1 − p̂)))`,必須 `h − h_P ≥ 2·σ_P`。**20 個判準全過**才算過;任一不過即不過。
- 任一 (s, h) 或任一 t 抽不滿 → **NOT EVALUABLE**,JSON 逐項列出 `(stock_id, half, k, pool_size)` 或 `(date, k, pool_size)`。

P_stock 吸收「這檔股票本來就常漲跌 3%」;P_date 吸收「那幾天整個市場都在動」。

### 3.4 檢定 D(方向:多出來的漲,不是同樣多出來的跌)

用 B 的**同一組抽樣**(同一個 seed 的同一批對照日),每組對照、每個 seed:

`(h − d) − (h_P − d_P) ≥ 2·σ_N`,其中 `σ_N = max(1, sqrt(h_P + d_P − (h_P − d_P)² / n))`

(σ_N 是對照組「漲次數減跌次數」的多項分配標準差,與 B 的 σ_P 同一個寫法、同一個 2。)**20 個判準全過**才算過。

**為什麼不是草案的 `h − drops > 0`**:那條只拿訊號跟自己比。多頭期間對照組的漲本來就多於跌,它會白白過關;日內偏空的期間又會白白失敗——它量到的是行情,不是訊號。要排除的對手假說是「訊號只預告波動」,而在那個假說下,訊號比對照多出來的漲與多出來的跌會一樣多;D 要求前者比後者多出 2σ。

### 3.5 檢定 C(兩半各自成立)

每一半、每組對照、每個 seed:`h(半) − h_P(半) > 0`(嚴格大於,只看正負)。擋「全部的優勢來自某一個月」。P_stock 依 (股票, 半段) 配對、P_date 依日期配對,兩臂在每一半內本來就等量。

### 3.6 伴隨計數(只報告,永遠不是判準,永遠不是補救)

- +5%、+7% 的漲/跌次數(訊號臂與兩組對照各一,同一批抽樣)。
- **買不到的那一天**:v(t)(t+1)開盤到收盤漲 ≥ 3% / 跌 ≥ 3% 的次數(訊號臂與兩組對照,同一批抽樣、各自的 v)。用途只有一個:若 D 或 B 不過、而這一列明顯偏高,代表訊號可能真的有內容、只是**在現行匯入時點下買不到**——那是「改匯入時點」的產品問題,要另開 v2、只用之後的交易日,**不得**用它改變本次裁決。
- `entry_open_at_limit_proxy`;依月份的 events / hits / drops;同一檔兩個契約同日舉旗的次數;段落合併前的訊號日數(`all_signal_days`)與其 hits / drops;因 X 剔除的訊號日數與事件數;因母體排除(ETF)的訊號日數;各否決計數(事件與池子分開)。

### 3.7 裁決與紀錄

- A 過、B 可評估且 20 判準全過、D 20 判準全過、C 40 判準全過 → **SHIP**。其餘一律 **DO NOT SHIP**,理由依序取第一個成立者:`underpowered` → `not_evaluable` → `informativeness_failed`(B) → `direction_failed`(D) → `consistency_failed`(C)。
- `direction_failed` 時 STATUS 照寫:「多出來的漲,大致被同樣多出來的跌抵掉;這個訊號預告的是波動,不是上漲。」——那是一個有用的結論,但不是使用者要的功能,不上線。
- 每次執行把 §1 全部欄位、每組對照每個 seed 的 h_P / d_P / σ_P / σ_N、H1/H2 邊界與每半的 h / h_P、否決計數、§3.6 伴隨計數、評估期起訖、X 的起訖、as_of、本文件 commit hash、第幾次執行、裁決寫進 STATUS;原始 JSON 進 `docs/evidence/`。
- **重跑**:UNDERPOWERED 或 NOT EVALUABLE 是無結果——自上一次的 as_of 起累積 ≥ 60 個新市場交易日才可重跑一次,同一套規則、記次數。B / C / D 不過是**結果**:收案,不重跑;要改條件只能 v2。

### 3.8 不允許的補救(在看到資料之後)

### 3.9 上線之後

- 匯出每晚用**同一個函式**、從 `from` 起累計重算 §1 那幾個整數(export 自己重寫一次就是第二條規則)。

5. **只有 SHIP** 才上線:`radar.json` 加一個頂層鍵 `futures_signal_next_day`,內容就是 §1 表格;三態同 `docs/38` §7.5(沒有鍵 = 沒算過)。補 `RATIO_ISH + RANK_ISH` 閘門與「就是 §1 那幾個鍵、沒有第 N+1 個」的形狀鎖。期貨分頁與個股期貨分頁各加兩句,由 `lib/` 純函式產出、逐字鎖住:
   > 「{from} 至 {to},期貨量創新高、而當天現貨量還沒創新高的訊號共 {events} 次。訊號要到下一個交易日晚上才看得到,所以從再下一個交易日的開盤買、當天收盤算:漲 ≥ {threshold_pct}% 的有 {hits} 次,跌 ≥ {threshold_pct}% 的有 {drops} 次。同一批股票平常的日子(抽樣 10 組):漲 {placebo_stock_hits.min}–{placebo_stock_hits.max} 次、跌 {placebo_stock_drops.min}–{placebo_stock_drops.max} 次;同一天其他有期貨的股票:漲 {placebo_date_hits.min}–{placebo_date_hits.max} 次、跌 {placebo_date_drops.min}–{placebo_date_drops.max} 次。」
   > 「這是次數,不是機率;不含開盤跳空,開盤即漲停算沒漲到;未扣手續費與交易稅;每檔股票沒有自己的數字。」

## 7. 沒被問到、但會讓結果不誠實的地方(事前承認)

- **群聚**:同一天多檔一起舉旗(大盤日、指數調整、除權息季)會讓二項 σ 偏樂觀。P_date 吸收水準,C 擋集中在某一段,D 擋純波動;剩下的群聚仍在——這是要求 20 + 20 + 40 個判準全過的理由,不是被治好的問題。
- **除權息季的機械性旗標**:6–9 月除權息季「以期代現」等股利稅務操作會讓期貨量放大而現貨沒有,產生沒有資訊的 F_only。開盤到收盤用同一列原始價,不受除息跳空影響;這些旗標只會**稀釋**效果,方向是更難過關。不另外過濾,也不得事後拿來當補救理由。
- **存活偏誤**:母體是 `futures_contracts` 現有的標的;期間內被下市的契約不在裡面。兩臂同一個母體,偏誤不分臂。e 日沒有價格列的股票由 R1 否決並計數。
- **漲跌幅 10%**:開盤到收盤被上限截斷;開盤鎖漲停結構性未命中(R3),兩臂同規則。
- **處置股**:偵測不到(§2)。
- **成本**:+3% 是毛額;當沖交易稅與手續費約 0.4–0.45%,畫面句明講未扣。
- **可見性依賴現行管線**:e = t+2 是因為餵源沒有日期參數(`docs/38` §7.8)。日後若改成 t 晚上就看得到,本文件的計數仍是 t+2 的事實;t+1 進場是 v2。
- **兩個日曆**:台灣期貨與現貨交易日相同;若某天現貨整市場缺列,`S` 為未知,該日不產生訊號,也不是合格對照日。e 一律以 D 計。
